### 0.1.3 的本机实测（改的是延迟，不测就等于没改）

时间线，取自 2026-10-24 10:16 那次真启动（旧版 0.1.2 在跑，powershell 那条路）：

| 时刻 | 事件 | 相对主进程 |
| --- | --- | --- |
| 10:16:02.982 | Electron 主进程起（pid 21924） | 0 |
| 10:16:03.238 | 主窗口已创建（渲染进程 34248 起来的时刻），此刻**隐藏**、尺寸 1280×820 | +0.26s |
| 10:16:03.549 | 宿主进程起（pid 35720，父进程正是 21924 → 插件认 PID 没问题） | +0.57s |
| 10:16:04.637 | 插件 `apply` 落地（`state.json.gen`） | +1.66s |
| 10:16:06.128 | `SetWindowPos` 把窗口改成 2200×1200（`state.json` 写入） | **+3.15s** |

同一条代理路的起进程耗时，本机两轮实测 1319ms / 1243ms；拆开来是起 `powershell.exe` 800/821/850ms
（三轮）＋ `Add-Type` 现场编译再加约 450ms。换成现编助手（同一台机器、同一套 P/Invoke）：

| 动作 | 实测 |
| --- | --- |
| `csc.exe` 现编一次（一次性，之后命中缓存） | 111ms |
| 起助手 + 第一次枚举（`openWinAgent`） | **98ms** |
| 起 powershell 代理 + 第一次枚举（同一函数走兜底） | 1568ms |
| 一次性 `--get` / `--set` | 84ms / 83ms |
| 进程常驻后再问一次 WA / SET | 2ms / 7ms |

照这条时间线，助手那条路把"动手"从约 +3.15s 挪到约 **+1.9s**，落在 `show()` 之前。
第一次装上新版的**那次**启动会额外付一次现编 + 首次执行的成本（exe 第一次跑约 2.1s，是杀软/文件缓存
冷），从第二次启动起就是上面那组数字 —— 也就是最坏的一次不如老路子，之后每次都比老路子快一秒多。

真窗口验证（不产生任何视觉变化）：对当时那个真实 DSH 主窗口下一次"原值 SET"，助手 83ms 返回 OK，
改后再读仍是 `(180,96) 2200×1200`。

### CI 上那 11 分钟（这就是重打一版的原因）

推上去之后五道 job：`desensitization`、`syntax-linux`、`manifest` 全绿；两台 `selftest-windows` 的
`Offline selftest` 步骤跑了 **11 分钟没结束**。更麻烦的是**未结束的 job 取不到日志** —— logs 接口实测回
`BlobNotFound`，也就是说"卡住的自检在 GitHub 上恰恰查不到"。

本机这边同一份代码整轮 10.6~12.5s：`[7]` 组（真起 6 个 powershell 代理）9.2~10.6s，`[7b]` 组（现编 +
4 次一次性调用 + 2 次常驻代理）2.9~4.4s；每次 Win32 调用又各自封顶（编译 20s、其余 8s），最坏预算约
3min —— 本机数字解释不了 11 分钟。先加"到点自杀 + 收尾明确退出"，日志立刻就能取了，真因随之浮出来，
**两条都是自检脚本自己的毛病**：

1. `[7b]` 里那条 `openWinAgent(助手)` 的断言在 runner 上必挂：CI 的 Windows runner 跑在 **session 0**，
   那里面没有 `Chrome_WidgetWin_1` 这个窗口类，探针枚举回的是**空数组**，而断言写的是"必须带回非空
   数组"。断言一抛就跳过了后面的 `agent.close()` —— 于是那个常驻助手进程一直挂在事件循环上，**node
   永不退出**，CI 只能干等 6 小时 job 超时。这就是那 11 分钟。
2. 加了明确退出之后又露出第二条：收尾 `fs.rmSync(tmp)` 删不掉临时目录里那个 exe —— Windows 不允许删
   **正在运行**的映像，`EPERM: unlink` 直接把已经打好的结论盖掉（runner 日志最后只剩一句
   `自检脚本自身出错： Error: EPERM …wsk-agent-e39174a19d671d27.exe`，98 通过 / 1 失败反倒看不见）。

于是这一版在发布前加固五处（旧那颗从未发布、也没打 tag，所以同版本号重打）：

1. 自检加 **8 分钟看门狗**：到点打红，并写明"日志里最后一条组头就是卡住的那组"（组头在跑该组之前打印）。
2. 收尾**明确 `process.exit`**（成功 0 / 失败 1），不再指望句柄自己排干；测试用的 http server 先
   `closeAllConnections()` 再 `close()`（一条没结束的 keep-alive 就够 `close()` 永远不 resolve）。
3. 两条 `openWinAgent` 检查改成 **`finally` 里关代理**：断言失败也不许把常驻子进程留在事件循环上。
4. "探针必须带回非空数组"改成**空数组是合法答复**（只要求有条目时字段齐），并补一条真断言：没有可比
   窗口时 `pickEarlyMainWindow(…, -1)` 必须认不出主窗。runner 上正是这种情形。
5. 临时目录清理带 `maxRetries: 10 / retryDelay: 300`，仍删不净就记成一条命名清楚的失败项
   （"临时目录没删净（说明有 Win32 子进程没退出）"），不再让异常盖掉结论。

另外一条与 CI 无关、但同一批日志暴露的口径：助手 `--protocol` 探针与助手代理单次请求超时 **4s → 8s**。
刚写出来的 exe 第一次执行会被杀软整份扫一遍（本机首跑就要 0.8~2.2s），4s 太紧会把"其实能用"误判成
"助手不可用"，白退回慢路。

两组 Win32 的耗时从此打进 CI 日志（`（本机实测：powershell 代理组 …ms，助手 exe 组（含现编）…ms）`）：
本机 9,200~10,600ms / 2,900~4,400ms，runner 上 5,844ms / 636ms —— 慢在哪一层以后不用再猜。
**助手这条路在 GitHub 的 Windows runner 上是真跑得通的**：`csc.exe` 现编、`--protocol` 握手、`--get`、
`--set`（假句柄如实回 `FAIL` 且退出码 0）四条全绿。

### 这一版修的两处实机缺陷（以及为什么不是"参数没调好"）

1. **设置页「当前主窗口外框」一直显示"读取中…"** —— 2026-10-19 i18n 那轮的回归：那行是用
   `setText(current, "current.loading")` 注册的，闭包**永久**留在 `sinks` 里，而 `applyState` 的最后一步
   就是 `localizeStatic()`（重放全部 sinks），于是每次成功取数后刚写进去的真实尺寸被当场覆写回去。
   现场排除过：GET 带 content-type 的 body 挂起、CORS 缺 ACAO、`client-modules` pkgMeta 自愈、客户端
   热推送、以及"桌面转发把 `Content-Encoding: gzip` 原样透传导致渲染端解不开"（`WITHHELD_RESPONSE_HEADERS`
   里明确剥掉 content-encoding / content-length / transfer-encoding，且用 Node 复刻透传两种写法都能
   `json()` 成功）。**定性靠 A/B**：同一份新自检跑 0.1.0 的 `lib/client.js` -> FAIL「首刷后那行不对：
   读取中…」；跑修好的那份 -> 88 项全绿。改法：那一行自己是一条 sink，文案按最新载荷现算。
2. **拖完马上退出会把这次拖动整个丢掉** —— 采样固定 15 秒，而 `state.json` 与退出兜底写的都是"最后一次
   **采样到**的矩形"，不是"最后一次真实矩形"。改成自适应：待机 `saveIntervalMs`（15s）→ 采到与上一轮
   不同就 `activeSampleMs`（1s）并保持 `activeTailMs`（10s），而且下一轮只在上一轮跑完之后才排（慢读取
   排队、不叠加）。另加 `followManualResize`（默认开）：采到宽高被手动改了就把「恢复尺寸」选择写成
   自定义 = 那个尺寸。
   真机实测（本机桌面端，从插件外部改窗口）：1850×980 -> 选择 **2.51 秒**后翻成 `自定义 1850×980`；
   快轮询尾巴内再改 1840×970 -> **1.29 秒**；插件自己 `/select` 改回 1920×1080 之后，过了一个待机节拍
   选择仍是具名 `1920x1080`（自我标记生效，具名分辨率不会被插件自己改成自定义）。
   **口径必须说清**：首次检测仍受待机节拍支配（最坏等满 15 秒，这次 2.5 秒是相位运气），"1 秒"指的是
   变化被看到之后的节奏；要压首检延迟就调小 `saveIntervalMs`（代价是每次都得起一个 PowerShell，
   冷启动约 0.7 秒）。
